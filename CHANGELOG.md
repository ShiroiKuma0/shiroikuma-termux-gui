# Changelog

This file carries the history of **白い熊 Termux GUI** ([ShiroiKuma0/shiroikuma-termux-gui](https://github.com/ShiroiKuma0/shiroikuma-termux-gui)), 白い熊's fork of [Termux:GUI](https://github.com/termux/termux-gui). Upstream ships no `CHANGELOG.md` — its per-versionCode notes live in `fastlane/metadata/android/en-US/changelogs/` and stay upstream's. Fork releases are listed newest first; each names the upstream commit it is built on, and only the first release lists everything built on top of stock — later entries are per-release deltas, with an "Upstream since" subsection distilling the upstream commits absorbed in between.

## 白い熊 Termux GUI 1.0.0+2025-06-25.23-38.gbe24a5f3+002 — 2026-09-13

First release of **白い熊 Termux GUI**, 白い熊's fork of [Termux:GUI](https://github.com/termux/termux-gui). It installs **over** the stock app (app id `com.termux.gui` kept) and is signed with the one key of the whole `com.termux` shared-UID family. This first entry lists everything built on top of stock.

**Upstream base:** [termux/termux-gui](https://github.com/termux/termux-gui), branch `main`, commit [`be24a5f3`](https://github.com/termux/termux-gui/commit/be24a5f3) (2025-06-25 23:38 UTC, "Added: Add `SECURITY.md`") — upstream's `versionName 1.0.0` / `versionCode 8`. This release is `versionCode 80002`.

**Artefact:** `shiroikuma-termux-gui_1.0.0+2025-06-25.23-38.gbe24a5f3+002_universal.apk` — one APK carrying the JNI library for `arm64-v8a`, `armeabi-v7a`, `x86` and `x86_64` (upstream builds no ABI splits).

### Major features

- **The 白い熊 Termux GUI UI page** (`com.termux.gui.shiroikuma.ShiroikumaUiActivity`), the house black-yellow page, built from programmatic Views (upstream has no `androidx.preference`). Three entry points: a **static launcher shortcut** 「白い熊 UI」 (`res/xml/shortcuts.xml`, declared on the settings activity; ignored on API 24, present from 25); a yellow **「白い熊 Termux GUI UI」 pill** inserted directly under the title of upstream's settings screen; and a **long-press on that title** (the screen has no toolbar). Both in-app hooks are the single line `ShiroikumaEntry.install(this)` at the end of `GUIConfigActivity.onCreate`.
- **Export / Import of the app's settings** as one ZIP, `shiroikuma-termux-gui_<yyyy-MM-dd_HH-mm-ss>.zip`, written as `<name>.part` and renamed only when complete. Inside: `manifest.json` (`format` = `shiroikuma-termux-gui`, `version` = 1, `app`, `appVersion`, `createdTs`, `categories[]`) followed by `settings.json` = `{"settings_prefs": {"<key>": {"t": "int|long|float|bool|string|set", "v": …}}}`.
  - The one category, **`settings`**, is upstream's four settings — service timeout, background, log level, "Allow JavaScript without dialog" — which live in the **encrypted** `settings_prefs` (`EncryptedSharedPreferences`). They are dumped and restored through the very handle `Settings` opens (its `settingsPreferences()` is now `internal` instead of `private` — the only change to that file), so the archive carries the decrypted values and a restore lands in the same keyset.
  - Deliberately **not** exported: `widgets_prefs` (the appWidgetId ↔ uuid map is dead after a reinstall) and the two device-local fork files (export directory, automation switch and token).
  - **Import** merges per key, only the categories the archive carries, every write `commit()`ed. The `javascript` key is **tighten-only**: an archive may switch the JavaScript confirmation prompt back on, never off (contract v2 §2a — an import must not silently weaken another surface); the result names what was held back. Archives over 16 MB, empty ones and ones carrying no categories are refused.
  - After an import the settings screen underneath is **refilled** from the restored values when it resumes — upstream writes its fields back in `onPause`, which would otherwise clobber the restore.
- **Sister-app backup-automation contract v2**, so 保存復元 (the 自由作業盤 batch) and 応用管理 can back the app up and restore it unattended — see *Backup & automation*.
- **Black-yellow traced launcher icon and the 白い熊 Termux GUI name** everywhere user-visible — see *UI & theming*.

### UI & theming

- **House look** (`ShiroikumaUi.kt`): black `#000000`, yellow ink `#FFFF00`, dim yellow `#C8C800` summaries, warning red for "not set"/"none"; section headings 20 sp bold with a text-wide underline and a hairline between sections; indent ladder 36 dp (section) → 72 dp (rows); tight rows (title 16 sp, summary 13 sp); dialogs black with a 2 dp yellow border, 16 dp radius and pill buttons.
- **Page sections and rows:** *Export / Import* — 「Export / Import…」 (opens the panel), 「Export directory」 (SAF `ACTION_OPEN_DOCUMENT_TREE`, persisted with a persistable permission; red "not set", and "Access lost — tap to grant it again" if the grant is gone), 「Last export」 (newest `shiroikuma-termux-gui_*.zip` in the directory, queried on resume off the main thread; red "none" / "no directory"), 「Automation export」 (switch, ON by default), 「Use authorization token?」 (switch, OFF by default), and the 「Authorization token」 row shown only while that is on (abbreviated `80922d8c…4c49a87c`; tap copies the full token; **Regenerate** behind a confirm). *Reset* — 「Reset 白い熊 UI settings」 clears the page's own `shiroikuma_ui` preferences file after a confirm and leaves the app's settings, the export directory and the automation rows alone (the file holds nothing yet; the row is in place for future page settings).
- **The Export / Import panel** (`ExportImportPanel.kt`, ported from raikidoban's): a transparent-window dialog with one bordered rounded black box — centred title, dim description, a tappable bordered directory box (red until set, yellow once set), the last-backup line, 全選択 plus one checkbox per category, and the pill row Cancel | Import · Export. A finished export ends in an info dialog (path · size · category count) whose OK **closes the whole chain** (dialog → panel → page); failures leave the panel open. An import picks from the backups in the directory (or 「Browse…」 for any file) and ends with 「Later」 / 「Restart now」. Progress text 「Exporting…」 / 「Importing…」 while the work runs off the main thread.
- **Launcher icon:** yellow `#FFFF00` stroke-only line art on black, redrawn from upstream's adaptive vector — the chevron, the open window frame with its dot, the underscore. One geometry model in `tools/icon/emit_launcher.py` emits `design/shiroikuma-termux-gui-icon.svg` (512 viewBox), the adaptive foreground `res/drawable/ic_launcher_foreground.xml` (upstream's `mipmap-anydpi-v26` wrappers untouched), the legacy `mipmap-*/ic_launcher{,_round}.webp` rasters for all five densities, `app/src/main/ic_launcher-playstore.png`, and `fastlane/metadata/android/en-US/images/icon.png`. Requires `rsvg-convert` and ImageMagick.
- **Name:** `app_name` = **白い熊 Termux GUI**, `app_settings` = **白い熊 Termux GUI Settings**; the four hard-coded `"Termux:GUI"` literals in Kotlin now read `R.string.app_name` — the foreground-service notification title (`GUIService.kt`), the logcat-dump file name (`GUIConfigActivity.kt`), and the notification-permission toasts (`protocol/protobuf/v0/HandleNotification.kt`, `protocol/json/v0/HandleRemote.kt`). `fastlane/metadata/android/en-US/title.txt` = 白い熊 Termux GUI. Code namespaces, style names (`Theme.TermuxGUI`, `TermuxAlertDialogStyle`), log tags, protocol names and the `Service` notification channel are untouched.
- All fork strings live in their own `res/values/shiroikuma_strings.xml`, so upstream's `strings.xml` differs from stock only in the two name strings.

### Backup & automation

- **§1 broadcast door** — the exported receiver `com.termux.gui.shiroikuma.automation.StateExportReceiver` answers `com.termux.gui.action.LIST_CATEGORIES` (inline: `OK:` + one `id⇥label⇥parent⇥on|off` line per category), `com.termux.gui.action.EXPORT_STATE` (validates `items`, then a **guarded** `startForegroundService` of `StateExportService`), and `com.termux.gui.action.CANCEL_EXPORT` (fire-and-forget; the running export deletes its partial and answers `ERROR:cancelled`). Extras: `token`, `path`, `items`, `progress_action`, `reply_action`, `reply_package`, `reply_id`. Exported with no permission by design — this half only ever writes where it is told to.
- **Destination rule:** this app holds **no storage permission at all**, so a caller's absolute `path` is always ignored in favour of the configured SAF export directory; with no directory set the reply is exactly `ERROR:no-storage-access` (a path was given) or `ERROR:no-directory` (none) — the keys 自由作業盤 turns into repair buttons.
- **§2a data door** — the exported provider `content://com.termux.gui.automation` (`AutomationProvider`) with four `call()` methods: `describe` (header JSON with `requires_permissions` `[]` and `requires_launch_first` `false`), `export` and `import` (validate, `dup()` the caller's descriptor, hand it to `AutomationDataService`, answer `OK:<job_id>` — the callee mints the id), and `cancel` (`OK:cancelled`). `import` exists **only** here. Refusals are returned as `ERROR:` strings, never thrown across the binder.
- **Caller verification** (`AutomationCallers`): an exact package name from the allow-list (応用管理 `shiroikuma.oyokanri`, 自由作業盤 `shiroikuma.jiyusagyoban`), the kernel uid cross-checked against that name, and the caller's **signing certificate pinned** by SHA-256 (`signingInfo` on API 28+, the `signatures` array below). Each failure has its own reason string: `caller unknown`, `caller not permitted`, `caller uid mismatch`, `caller signature mismatch`, `caller signature unreadable`.
- **The gate** (`AutomationAuth`): master switch 「Automation export」 (default **on**) and 「Use authorization token?」 (default **off**); the token is 24 `SecureRandom` bytes as hex, generated lazily, compared in constant time, regenerable; a token sent to an app that does not require one is ignored. Refusals: `ERROR:automation disabled`, `ERROR:bad token`. Every write is `commit()`ed so the gate fails open rather than silently reopening after a SIGKILL.
- **Two `dataSync` foreground services** (`StateExportService`, `AutomationDataService`) under the new `FOREGROUND_SERVICE_DATA_SYNC` permission, with a 「Backup automation」 notification channel (「Exporting settings…」 / 「Restoring settings…」). Every foreground start is guarded at all four sites; a refused start on a cold, non-battery-exempt app is answered with `ERROR:no-foreground-start` (the key that puts a 「電池最適化を除外」 button on the failed row), otherwise with a descriptive line. Exactly one terminal reply per request, sent as a fresh broadcast with `FLAG_INCLUDE_STOPPED_PACKAGES` and an explicit package (never a `ResultReceiver`, `PendingIntent` or ordered-broadcast result — EMUI severs those between third-party apps).
- **§3 progress** (`AutomationProgress`): real counts (`current` = position of the category being written, `total`, `item` = category id) written under both correlation names (`reply_id` / `job_id`), throttled to one message per 500 ms with the final one always sent, plus a heartbeat for quiet steps.
- **Manifest additions** (all additive, one fork block): `<queries>` for `shiroikuma.oyokanri` and `shiroikuma.jiyusagyoban` (without them the reply broadcasts' `setPackage()` fails silently on Android 11+), the receiver / provider / two services, and three integer `<meta-data>` for capability discovery without waking the app: `shiroikuma.automation.contract` = 2, `shiroikuma.automation.format` = 1, `shiroikuma.automation.min_format` = 1.
- **Shared core:** one implementation (`TermuxGuiExport.kt`) serves the panel, the §1 service and the §2a service — none carries export logic of its own.
- **Preferences files** introduced: `shiroikuma_ui` (the page's own), `shiroikuma_eximport` (`dir_uri`, device-local), `shiroikuma_automation` (`automation_enabled`, `automation_require_token`, `automation_token`, device-local).

### Identity & packaging

- **`applicationId`, `namespace` and `sharedUserId` unchanged** — `com.termux.gui` / `com.termux`. Every Termux:GUI client library (Python, C/C++, Bash, community bindings) hard-codes the package for the start broadcast to `com.termux.gui/.GUIReceiver` and the socket handshake, and the app must share UID `com.termux` with Termux to read the caller's files; renaming would orphan every client. The fork therefore **replaces stock Termux:GUI in place** and is told apart by label, icon, links, signing key and the UI page.
- **Signed with the one key of the `com.termux` shared-UID family** (`shiroikuma-termux`, `-api`, `-x11`, `-gui`, `shiroikuma-emacs`); a member signed with any other key fails to install with `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE`. Certificate SHA-256 `50:b4:7e:8f:…:96:04`.
- **Version scheme** `<upstream versionName>+<upstream base date>.<HH-MM>.g<sha8>+<NNN>` (the pin is `git merge-base HEAD main`, its committer time in UTC; `NNN` zero-padded in the name only), `versionCode` = upstream's × 10000 + N. Upstream's two literals in `app/build.gradle` are read, never edited, so a rebase brings a new base in by itself. `BUILD_NUMBER` runs monotonically and is never reset.
- **Links:** the README's release badge and links point at `ShiroiKuma0/shiroikuma-termux-gui`; `fastlane/…/full_description.txt` links our README. Knowingly left: upstream's `Protocol.md` links (the spec), the attribution link to upstream, and the F-Droid badge of stock `com.termux.gui` in upstream's README body.
- New fork README (this header, the highlight sections, family links, build instructions) above upstream's README body, and this `CHANGELOG.md` (upstream ships none; its per-versionCode notes stay in `fastlane/metadata/android/en-US/changelogs/`).

### Build pipeline

- **`app/shiroikuma.gradle`**, applied by the last line of `app/build.gradle` (the only change to that file besides that line): derives the fork version pair from upstream's literals through `providers.exec` (configuration-cache safe), creates the `release` signing config from the gitignored `keystore.properties`, declares the `androidx.documentfile:documentfile:1.0.1` dependency the page's SAF handling uses, and registers **`buildFork`**.
- **`buildFork`** — refuses at configuration time (before any CMake or R8 work) when `keystore.properties` is missing or the versionCode does not exceed `LAST_BUILT_VERSION_CODE`; runs `assembleRelease` (CMake JNI for four ABIs, R8 minify, our key); copies the APK to `~/tmp/shiroikuma-termux-gui_<versionName>_universal.apk`, refusing to overwrite an existing file; prints the path, versionName and versionCode; bumps `BUILD_NUMBER` and records `LAST_BUILT_VERSION_CODE` in `gradle.properties`.
- `gradle.properties` carries `BUILD_NUMBER` and `LAST_BUILT_VERSION_CODE`; `keystore.properties_sample` documents the signing file; `.gitignore` adds `keystore.properties`, `*.jks` (upstream's tracked debug `app/dev_keystore.jks` stays tracked), `.claude/settings.local.json` and `.scratch/`.
- Repo agent docs: `CLAUDE.md`, `.claude/skills/build-apk` (build + delivery) and `.claude/skills/upstream-new-version` (upstream sync with the proceed-gated changes table).
- Build history: `+001` (versionCode 80001, 2026-09-13) was the first de-branded build; `+002` (versionCode 80002, 2026-09-13, this release) adds the UI page, Export / Import and the backup automation.
